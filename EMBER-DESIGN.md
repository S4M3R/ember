# Design: Ember — a counterfactual prompt-attribution debugger for voice agents

Generated by /office-hours on 2026-05-30
Event: YC Voice Agents Hackathon (Cekura + Daily; NVIDIA, AWS, Twilio)
Status: DRAFT
Mode: Builder (hackathon, submissions due 6:00 PM, 60-second demos)

> Working name "Ember" = turn the black box into a glass box. Rename freely.

## Problem Statement
A voice agent is a black box to its own developer. When it fails — hallucinates a
refund, forgets a constraint, picks the wrong tool — you get a transcript and a
score, but no idea *which part of your 2,000-token system prompt caused it*. So you
guess, edit the whole prompt, re-run, and hope. Ember shows you the exact prompt
block responsible for any given response, so you fix only that block.

## What Makes This Cool
The "which parts of the prompt influenced this response" question is a **counterfactual**:
knock out a prompt block, re-score the response the agent actually gave, and measure how
much less likely it becomes. Replay (time-travel) and attribution are therefore the *same
engine*. The artifact is a live, visual debugger: a turn timeline (Cekura failures pinned
to it) + a system-prompt saliency heatmap + edit-one-block-and-replay. It's developer
infrastructure for the exact people judging — Pipecat (the pipeline), NVIDIA (the model),
Cekura (the eval).

## Key Architecture Decision: attribution = ablate + log-likelihood drop
For a failing turn with response R and system prompt split into blocks {b1..bk}:
- Baseline score = sum of token logprobs of R given the full prompt.
- For each block bi: remove bi, rescore R, attribution(bi) = baseline − ablated.
- Large positive drop ⇒ bi caused R. Render as a heatmap over the prompt blocks.

**Fast path (exploit this):** Nemotron is likely served by vLLM. Use the
`/v1/completions` endpoint with `echo=True, max_tokens=0` and `logprobs`/`prompt_logprobs`
to score `prompt + R` in a single forward pass — no generation. K scoring calls per turn,
fired in parallel. This is why Nemotron is the *better* model for the centerpiece (GPT-4.1
can't echo-score arbitrary completions cleanly) — a real reason to feature NVIDIA.

**CRITICAL-PATH SPIKE (first 30 min, before anything else):** confirm the Nemotron ALB
endpoint exposes `echo`/`prompt_logprobs`. Test:
`curl $NEMOTRON_LLM_URL/completions -d '{"model":"...","prompt":"...","echo":true,"max_tokens":0,"logprobs":1}'`
- If yes → build as designed.
- If no → fallback: ablate + output-semantic-delta or Cekura-score-delta (model-agnostic,
  slower, bulletproof). Decide by minute 30. Do not let this block you past lunch.

## Approaches Considered
### Approach A — Minimal winning slice (RECOMMENDED for the time box)
Clickable list of turns (not a frame-accurate scrubber). One failing turn, precomputed
saliency heatmap, edit the hot block, replay that single turn at `temperature=0`, show the
output flip + Cekura re-score green. Reuses: Pipecat starter, Cekura MCP, vLLM echo-scoring.
Effort: M. Risk: Med. This is the 60-second demo end to end.

### Approach B — Full time-travel replay debugger
Frame-accurate timeline scrubber, fork from any turn, swap model (Nemotron↔GPT) or prompt,
diff outcomes. Effort: L. Risk: High in a 1-day box. Do this ONLY if A is solid by ~3 PM.

### Approach C — Live attribution on every turn (stretch)
Run ablation scoring live as you talk, heatmap updates in real time. Effort: L, depends on
endpoint latency. Great wow if it lands; keep as post-A stretch, precompute for the demo.

## Recommended Approach
A as the spine. Treat B/C as stretch goals layered on the same engine once A demos cleanly.
Protect the 60-second path above all — a working A beats a half-built B every time.

## Architecture (concrete)
- **Agent:** fork `yc-voice-agents-hackathon/server`, run `bot-nemotron.py`. SmallWebRTC for
  local; Twilio optional.
- **Capture:** Pipecat frame observer logs per-turn `{messages, response, latencies, tool_calls}`
  to a structured session file (JSONL). System prompt authored as labeled blocks (e.g.
  `## ROLE`, `## CATALOG RULES`, `## REFUND POLICY`) so blocks are first-class.
- **Attribution service:** small FastAPI/Python service. Given a turn, splits the prompt by
  block, fires K parallel echo-scoring calls to Nemotron, returns per-block logprob drops.
- **Cekura:** run `/cekura-report` to get failing scenarios; map each failure to its turn;
  pin to the timeline. Re-run the single fixed scenario to show the green flip.
- **Viz:** web front end (React + a fast canvas/SVG). Three panels: turn timeline (Cekura
  pins) · prompt heatmap · response + replay button. Make it beautiful — the viz is the win.

## Success Criteria
- Live: talk to the agent, see turns appear with latencies.
- Cekura failure pinned to the exact turn.
- Saliency heatmap correctly fingers the responsible prompt block on the demo turn.
- Edit that block → replay → response changes → Cekura score flips to pass.
- Whole thing readable in 60 seconds without narration.
